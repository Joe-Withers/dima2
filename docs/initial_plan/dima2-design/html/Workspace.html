Comment anchoring

Problem

1

Review comments must survive edits elsewhere in the file. Line numbers drift whenever the agent rewrites an earlier section, and quoted-text search breaks on small wording changes.

Approach

2

The preview renderer stamps a stable data-block-id on each heading, paragraph and list item at render time. A comment stores (file_path, block_id, body, created_at, sent_at).

Failure modes

3

If the block itself is edited, its id changes and the comment is flagged "block not found". If the block is removed, the comment stays in history, unanchored.

Comments are never deleted on send. They're marked sent with a timestamp and stay resolvable, so each file keeps a review history.
